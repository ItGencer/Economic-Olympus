\# План проєкту: Економічна Монополія (веб-гра, онлайн з першого дня)



\## 0. Технологічний стек (фіксовано, не змінювати по ходу)



\- \*\*Frontend:\*\* Next.js 14 (App Router) + TypeScript + Tailwind CSS

\- \*\*Стан гри / БД:\*\* Supabase (Postgres) + \*\*Supabase Realtime канали\*\*

&#x20; (кожна гра = окремий канал `game:{game\_id}`)

\- \*\*Ігрова логіка (кидок, тригери клітинок, гроші):\*\* виконується

&#x20; \*\*на сервері\*\* — Postgres RPC-функції (`supabase/functions` або SQL

&#x20; functions), а НЕ в браузері. Клієнт лише надсилає намір дії

&#x20; ("кинути кубик"), сервер рахує результат і пише новий стан.

&#x20; Це обов'язково для чесного онлайну: інакше гравець з іншого браузера

&#x20; може підмінити локальний стан і "намалювати" собі виграш.

\- \*\*Auth:\*\* Supabase Anonymous Auth (без пароля) — гравець отримує

&#x20; тимчасовий `user\_id`, прив'язаний до `session\_id` гри. Реєстрація не

&#x20; потрібна, це знижує поріг входу.

\- \*\*Хостинг:\*\* Vercel (frontend) + Supabase (backend, безкоштовний тариф)

\- \*\*Дошка:\*\* SVG/CSS-grid рендер двох кіл клітинок з конфіг-масиву (не хардкод)



\*\*Архітектура одним реченням:\*\* гра завжди онлайн-мультиплеєрна за

замовчуванням; "гра на одному пристрої" — це просто кілька вкладок/сидінь

одного браузера, підключених до тієї самої сесії, а не окремий режим коду.



\*\*Чому сервер рахує логіку, а не клієнт:\*\*

\- гравці можуть бути в різних країнах — джерело правди має бути одне

\- унеможливлює читинг з грошима/акціями

\- знімає проблему "два гравці одночасно натиснули кубик" (race condition) —

&#x20; Postgres-транзакція просто відхилить дію не в свою чергу



\*\*Чому Codex — так:\*\* Codex — агентний інструмент, він читає файли

репозиторію напряму. Тому найдешевший (по токенах) спосіб роботи —

тримати "джерело правди" у файлах репозиторію (`GAME\_SPEC.md`,

`schema.sql`, `types.ts`, і цей план) і в кожному завданні писати Codex

"керуйся файлом X" / "виконай завдання №N з цього плану", а не переказувати

правила заново в кожному промпті.

\## 1. Файли-джерела правди (створюються ПЕРШИМИ, окремим завданням)



\### 1.1 `GAME\_SPEC.md` — правила гри у структурованому вигляді

Переробити ваш текстовий опис у формальний список:

\- усі типи клітинок (Сделка, Казино, Імідж, Random, Негативна репутація,

&#x20; Зарплата, Податкова, Реклама, Позитивна репутація, Клієнт, Тендер, Компанія,

&#x20; Директор) з точною формулою розрахунку для кожної

\- умови переходу внутрішнє→зовнішнє коло

\- умови боргу і повернення на Start

\- умови перемоги (вибори Генерального директора)



\### 1.2 `board-config.json` — масив усіх клітинок дошки

Кожна клітинка = об'єкт `{ id, ring: "inner"|"outer", type, params }`.

Це дозволяє логіці клітинок бути generic (один обробник на тип), а не

захардкодженим списком if/else на 40+ клітинок.



\### 1.3 `types.ts` — TypeScript-типи

`Player`, `GameState`, `Cell`, `Deal`, `Tender`, `Company`, `Director`, `Turn`.



\### 1.4 `schema.sql` — Supabase-схема

Таблиці: `games` (з полями `status`: `lobby`|`in\_progress`|`finished`,

`join\_code`, `max\_players`, `current\_turn\_player\_id`), `players`

(`game\_id`, `user\_id` анонімний, `seat\_number`, `is\_bot`), `game\_log`,

`companies`, `shares`, `tenders`, `directors`.

Одна `games.state` (jsonb) як snapshot повного стану гри — клієнти

підписуються на зміни цього поля через Realtime і просто перемальовують UI.



\*\*Правило лобі:\*\* приєднання дозволене тільки поки `games.status = 'lobby'`.

RPC-функція `join\_game(join\_code)` перевіряє це і кількість гравців (2–6)

перед вставкою рядка в `players`. Після виклику `start\_game(game\_id)`

статус міняється на `in\_progress` і `join\_game` для цієї гри більше не

спрацює (перевірка на рівні самої функції, не тільки UI).



\*\*Промпт для Codex (завдання №1):\*\*

> Прочитай мій текстовий опис гри (додаю файл rules-source.txt). Створи на його

> основі GAME\_SPEC.md, board-config.json, types.ts та schema.sql за описаною

> структурою. Не пиши код гри — тільки ці 4 файли.

\## 3. Як писати промпти Codex (щоб економити токени і не ламати код)



\- Один промпт = один рядок з таблиці вище, не більше.

\- Завжди починати з: \*"Керуйся GAME\_SPEC.md, board-config.json, types.ts.

&#x20; Онови тільки \[файли]. Не рефактор інше без потреби."\*

\- Не вставляти текст правил у промпт — Codex сам відкриє GAME\_SPEC.md з репо.

\- Після кожного етапу — швидкий ручний тест, коміт, і тільки тоді наступний.

\- Якщо Codex пропонує змінити типи з `types.ts` — це сигнал зупинитись і

&#x20; оновити спек-файл вручну, а не дозволяти "розповзання" структур даних.
