# Економічна Монополія - GAME SPEC

Цей файл є джерелом правди для правил гри. Клієнт ніколи не рахує кидки,
гроші, акції, тендери або перемогу самостійно: він лише надсилає намір дії,
а серверна Postgres RPC-функція виконує розрахунок у транзакції та оновлює
`games.state`.

## 1. Базові константи

| Параметр | Значення |
| --- | --- |
| Кількість гравців | 2-6 |
| Стартовий баланс | 10000 |
| Стартовий імідж | 0 |
| Стартовий товарний запас | 0 |
| Початкове коло | `inner` |
| Початкова клітинка | перша клітинка внутрішнього кола, `Start` |
| Статуси гри | `lobby`, `in_progress`, `finished` |
| Рух | вперед по поточному колу на результат кидка кубика |
| Джерело випадковості | тільки сервер |

## 2. Гравець

Гравець має:

- ім'я, яке можна змінювати;
- баланс;
- імідж;
- товарний запас;
- поточне коло та позицію на ньому;
- кількість успішних і провалених сделок;
- акції компаній;
- куплені тендери;
- статуси директорів;
- ознаку бота;
- боргове блокування для виходу на зовнішнє коло.

Гравці ходять по черзі. Будь-яка RPC-функція, що змінює стан гри, спочатку
перевіряє `games.current_turn_player_id`. Дія не у свою чергу відхиляється.

## 3. Дошка

Дошка складається з двох кілець:

- `inner` - внутрішнє коло;
- `outer` - зовнішнє коло.

Порядок клітинок визначається масивом у `board-config.json`. Рух за межу
масиву переходить на початок того самого кільця.

Внутрішнє коло містить типи клітинок:

- `start`;
- `casino`;
- `random`;
- `vacation`;
- `deal`;
- `image`;
- `negative_reputation`;
- `salary`.

Зовнішнє коло містить типи клітинок:

- `image`;
- `tax`;
- `negative_reputation`;
- `advertising`;
- `casino`;
- `salary`;
- `vacation`;
- `client`;
- `random`;
- `director`;
- `positive_reputation`;
- `tender`;
- `company`.

## 4. Життєвий цикл ходу

1. Сервер перевіряє, що гра має статус `in_progress`.
2. Сервер перевіряє, що діє `current_turn_player_id`.
3. Якщо у гравця `skipTurns > 0`, сервер зменшує `skipTurns` на 1, завершує хід
   без кидка та передає чергу наступному гравцю.
4. Сервер кидає один кубик `d6` для руху.
5. Гравець рухається вперед на результат кидка по своєму поточному колу.
6. Сервер запускає обробник типу клітинки.
7. Після обробки сервер перевіряє борг і доступність переходу на зовнішнє коло.
8. Якщо немає незавершеної дії, сервер передає чергу наступному гравцю.

## 5. Формули клітинок

### 5.1 `start` - Start

Формула:

- баланс не змінюється;
- імідж не змінюється;
- товарний запас не змінюється;
- використовується як точка старту та як точка повернення при боргу.

Автоматичної виплати за проходження `Start` немає. Виплати виконує тільки
клітинка `salary`.

### 5.2 `deal` - Ділова зустріч

Коли гравець потрапляє на клітинку, сервер створює картку:

- `coefficient = randomInt(5, 50)`;
- `unitValue = 1000`.

Гравець обирає `roll` або `decline`.

Якщо `decline`:

- баланс не змінюється;
- ділова зустріч не рахується успішною або проваленою.

Якщо `roll`:

- сервер кидає `d20`, тобто число від `1` до `20`;
- `score = coefficient + d20`;
- якщо `score <= image`, зустріч успішна;
- якщо `score > image`, зустріч провалена;
- `amount = (image - score) * unitValue`.

Після кидка гравець бачить `d20`, `score`, результат і суму. Баланс змінюється
тільки після кнопки `Підтвердити`:

- успіх: `balance += amount`, `successfulDeals += 1`;
- провал: `balance += amount`, де `amount` від'ємний, `failedDeals += 1`.

Після успішної ділової зустрічі сервер перевіряє можливість переходу на
зовнішнє коло.

### 5.3 `casino` - Казино

Коли гравець потрапляє на клітинку `casino`, відкривається картка казино.

Гравець має два варіанти:

- `decline` - відмовитися від гри в казино. Картка закривається, баланс не змінюється, хід переходить до наступного гравця.
- `accept` - зіграти в казино. Після згоди гравець вводить ставку та обирає `even` або `odd`.

Обмеження:

- гравець може робити ставку тільки якщо `balance > 0`;
- `stake >= 0`;
- `stake <= balance`;
- якщо баланс менший за ставку, сервер відхиляє дію.

Формула:

- сервер кидає `2d6`, тобто два шестигранні кубики;
- `diceSum = die1 + die2`;
- `parity = even`, якщо `diceSum % 2 = 0`, інакше `odd`;
- після кидка гравець бачить обидва кубики та їх суму;
- якщо `parity` збігається з вибором гравця, гравець натискає кнопку запуску коефіцієнта;
- сервер випадково визначає множник `multiplier = randomInt(2, 10)`;
- виграш рахується як `payout = stake * multiplier`;
- після показу коефіцієнта і суми виграшу гравець натискає `Отримати`;
- тільки після `Отримати` сервер додає виграш до балансу: `balance += payout`;
- якщо `parity` не збігається з вибором гравця, гравець бачить програш і натискає `Погодитись`;
- тільки після підтвердження програшу сервер списує ставку: `balance -= stake`.

Приклад:

- гравець обрав `even`;
- ставка `1000`;
- кубики дали суму `10`, тобто парне число;
- множник зупинився на `x8`;
- гравець отримує `1000 * 8 = 8000`, і ця сума додається до балансу.

Якщо гравець обрав `even`, але сума кубиків непарна, гравець програє ставку: `balance -= stake`.

### 5.4 `image` - Імідж

Коли гравець потрапляє на клітинку, сервер створює пропозицію:

- `imageGain = randomInt(2, 5)`;
- `price = randomInt(100, 3000)`.

Якщо гравець відмовляється:

- баланс і імідж не змінюються.

Якщо гравець погоджується:

- потрібно `balance >= price`;
- `balance -= price`;
- `image += imageGain`.

### 5.5 `random` - Random

Сервер створює випадкову подію з параметрів клітинки:

- `amount = randomInt(minAmount, maxAmount)`;
- `sign = randomChoice(["positive", "negative"])`, якщо знак не заданий у
  `params`.

Формула:

- якщо `sign = "positive"`, тоді `balance += amount`;
- якщо `sign = "negative"`, тоді `balance -= amount`;
- після перегляду події гравець натискає `Далі`.

### 5.6 `negative_reputation` - Негативна репутація

Коли гравець потрапляє на клітинку, сервер створює картку негативної
репутації.

Етапи:

- перше натискання `Старт`: сервер кидає `d6`, тобто число від `1` до `6`;
- друге натискання `Старт`: сервер визначає `multiplier = randomInt(1, 5)`;
- `imageLoss = d6 * multiplier`;
- гравець бачить результат і натискає `Далі`;
- тільки після `Далі`: `image -= imageLoss`.

Імідж може стати менше нуля. В усіх формулах, де використовується імідж,
від'ємний імідж погіршує результат.

### 5.7 `positive_reputation` - Позитивна репутація

Формула:

- `image += 1`.

### 5.8 `salary` - Зарплата / премія

Формула:

- якщо `image > 0`, тоді `balance += image * 500`;
- якщо `image <= 0`, баланс не змінюється.

### 5.9 `tax` - Податкова

Формула:

- `taxBase = max(balance, 0)`;
- `taxAmount = floor(taxBase * 0.2)`;
- `balance -= taxAmount`.

Якщо баланс уже від'ємний, податок дорівнює `0`.

### 5.10 `advertising` - Реклама

Коли гравець потрапляє на клітинку, сервер створює пропозицію:

- `price = randomInt(100, 1000)`;
- `imageGain = randomInt(1, 10)`.

Якщо гравець відмовляється:

- баланс і імідж не змінюються.

Якщо гравець погоджується:

- потрібно `balance >= price`;
- `balance -= price`;
- `image += imageGain`.

### 5.11 `client` - Клієнт

Сервер створює клієнта:

- `relationship = randomInt(1, 6)`.

Гравець обирає `accept` або `decline`.

Якщо `decline`:

- баланс і товарний запас не змінюються.

Якщо `accept`:

- сервер кидає кубик гравця `playerDie = d6`;
- сервер кидає кубик банку `bankDie = d6`;
- `playerScore = playerDie + image`;
- `bankScore = bankDie + relationship`;
- `difference = playerScore - bankScore`;
- `percent = clamp(difference * 10, 0, 100)`;
- гравець обирає `stockToSell`;
- `soldStock = min(stockToSell, inventory)`;
- `revenue = floor(soldStock * percent / 100)`;
- `inventory -= soldStock`;
- `balance += revenue`.

`clamp(value, 0, 100)` означає, що результат не може бути меншим за `0` або
більшим за `100`.

### 5.12 `tender` - Тендер

У грі є 6 тендерів:

| Країна | Викуп | Ціна платежу |
| --- | ---: | ---: |
| Україна | 4000 | 400 |
| Німеччина | 3000 | 300 |
| Мексика | 5000 | 500 |
| Бразилія | 8000 | 800 |
| Італія | 5000 | 500 |
| Франція | 6000 | 600 |

Формула:

- якщо тендер не має власника, гравець може купити його:
  - потрібно `balance >= buyout`;
  - `balance -= buyout`;
  - `tender.ownerPlayerId = player.id`;
- якщо тендер належить іншому гравцю:
  - `payer.balance -= price`;
  - `owner.balance += price`;
- якщо тендер належить поточному гравцю:
  - баланс не змінюється.

### 5.13 `company` - Компанія

У грі є 6 компаній. У кожній компанії рівно `100` акцій.

Формула купівлі акцій:

- гравець обирає `shareCount`;
- `shareCount > 0`;
- `companySoldShares + shareCount <= 100`;
- `cost = shareCount * sharePrice`;
- потрібно `balance >= cost`;
- `balance -= cost`;
- `shares[playerId][companyId] += shareCount`;
- `inventory += shareCount * inventoryPerShare`.

Контроль компанії:

- `ownershipPercent = shares[playerId][companyId]`, бо 100 акцій = 100%;
- якщо `ownershipPercent >= 51`, гравець може претендувати на директора цієї
  компанії.

Неможливо продати або купити акції так, щоб загальна кількість акцій компанії
перевищила `100`.

### 5.14 `director` - Директор

Коли гравець потрапляє на клітинку директора, сервер перевіряє всі компанії,
де гравець має `>= 51%` акцій.

Формула:

- якщо для такої компанії ще немає активного директора:
  - гравець може стати директором;
  - створюється `Director` зі статусом `active`;
  - `votingCoefficient = 1`;
  - `voteDifficulty = 7`;
- якщо активний директор уже є, клітинка не змінює стан.

Гравець може бути директором кількох компаній, якщо має контрольний пакет у
кожній з них.

### 5.15 Вибори Генерального директора

Вибори Генерального директора є умовою перемоги.

Гравець може ініціювати вибори, якщо:

- він є активним директором хоча б однієї компанії;
- у грі є хоча б один активний директор.

Формула голосування:

- для кожного активного директора сервер кидає `2d6`;
- `directorVotePower = ownershipPercent(company, director.playerId) * votingCoefficient`;
- `candidateResult = diceSum + candidate.image`;
- якщо `candidateResult >= director.voteDifficulty`, директор підтримує
  кандидата;
- `supportVotes += directorVotePower` для кожного директора, який підтримав;
- `totalVotes = sum(directorVotePower)` для всіх активних директорів;
- `supportPercent = supportVotes / totalVotes * 100`.

Якщо `supportPercent >= 51`:

- `games.status = "finished"`;
- `winnerPlayerId = candidate.id`;
- гра завершується перемогою кандидата.

## 6. Перехід на зовнішнє коло

Гравець може перейти з `inner` на `outer`, якщо одночасно виконано:

- `balance > 0`;
- `debtLocked = false`;
- `successfulDeals >= 7`.

Після кожної успішної ділової зустрічі, якщо умови виконано, сервер може створити
pending-choice:

- `move_to_outer`;
- `stay_inner`.

Якщо `successfulDeals >= 10`, сервер зобов'язаний запропонувати цей вибір після
успішної ділової зустрічі.

Якщо гравець обирає `move_to_outer`:

- `ring = "outer"`;
- позиція стає першою клітинкою зовнішнього кола, позначеною `entry: true` у
  `board-config.json`;
- баланс, імідж, товарний запас, акції, тендери та директорські статуси
  зберігаються.

Якщо гравець обирає `stay_inner`:

- гравець лишається на поточній клітинці внутрішнього кола;
- наступні успішні ділові зустрічі знову можуть створювати такий вибір.

## 7. Борги

Борг виникає, коли `balance < 0`.

Якщо `balance < 0` на зовнішньому колі:

- `ring = "inner"`;
- позиція стає `Start`;
- `debtLocked = true`;
- усі активи зберігаються.

Поки `debtLocked = true`, гравець не може перейти на зовнішнє коло.

Коли `balance >= 0`:

- `debtLocked = false`;
- гравець знову може виконати умови переходу на зовнішнє коло.

## 8. Боти

Боти є звичайними гравцями з `isBot = true`. Вони діють за тими самими
правилами, а їхні рішення все одно виконуються через серверні RPC-функції.

Мінімальні правила рішень бота для першої реалізації:

- приймати ділову зустріч, якщо `image >= 0` або `balance > 3000`;
- купувати імідж або рекламу, якщо вистачає балансу після покупки лишити
  мінімум `1000`;
- у казино ставити не більше `10%` позитивного балансу;
- купувати тендер або акції, якщо після покупки баланс лишається позитивним;
- ініціювати вибори Генерального директора, коли бот має хоча б одного
  директора.
