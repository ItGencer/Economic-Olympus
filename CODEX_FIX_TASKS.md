# Завдання для Codex: синхронізація авторизації + кабінет гравця

## Контекст

Google-логін через Supabase Auth уже працює: після кліку "Увійти через
Google" користувач реально створюється в Supabase (Authentication → Users),
сесія встановлюється. Проблема суто на фронтенді — стан "залогінений" не
поширюється по всьому застосунку.

## Завдання 1 — Єдине джерело стану авторизації

- Переконатись, що є один спільний `AuthProvider` (React Context), який:
  - при монтуванні застосунку викликає `supabase.auth.getSession()`
  - підписується на `supabase.auth.onAuthStateChange((event, session) => ...)`
  - зберігає `user` (або `null`) в контексті
- **Header-компонент** (шапка сайту з кнопкою "Увійти") має читати
  користувача з цього самого контексту через хук, наприклад `useAuth()`.
- Якщо `user` існує — замінити кнопку "Увійти" на:
  - аватар/ім'я користувача (з Google-профілю: `user.user_metadata.full_name`,
    `user.user_metadata.avatar_url`, якщо доступні)
  - випадаюче меню або кнопку "Вийти" (`supabase.auth.signOut()`)
- **AuthModal** (модальне вікно логіну) також має брати стан з того ж
  контексту, а не мати власний ізольований стан.
- Перевірити: після успішного логіну модальне вікно само закривається
  БЕЗ перезавантаження сторінки, і шапка одразу оновлюється.

## Завдання 2 — Особистий кабінет гравця

- Нова сторінка `app/profile/page.tsx`, доступна тільки залогіненим
  користувачам (якщо `user === null` — редірект на головну з відкриттям
  модального вікна логіну).
- Показує:
  - ім'я/email/аватар з Google-акаунту
  - список ігор користувача: активні (`status = 'in_progress'`), лоббі
    в очікуванні (`status = 'lobby'`), завершені (`status = 'finished'`)
    — робиться через `select` з таблиці `players` (join `game_id`) з RLS,
    відфільтроване по `user_id = auth.uid()`
  - просту статистику (кількість зіграних ігор, перемог — можна поки
    заглушку з нулями, якщо статистика ще не рахується десь окремо)
- Додати посилання "Кабінет" у Header поруч з аватаром/іменем користувача
  (з завдання 1), видиме тільки залогіненим.

## Завдання 3 — Діагностика "не вдається почати гру"

**УВАГА: не виправляти наосліп.** Спершу відтворити сценарій:
1. Залогінитись через Google
2. Натиснути "Створити гру"
3. Зафіксувати точну поведінку і будь-які помилки в консолі браузера
   (Network tab теж перевірити — чи взагалі йде запит до `create_game` RPC,
   і яка відповідь)

Якщо запит на `create_game` йде і повертає помилку — вивести текст цієї
помилки користувачу на екрані (не просто в консоль), щоб наступного разу
її було видно без F12.

Якщо запит взагалі не йде — перевірити, чи кнопка "Створити гру" на
головній сторінці правильно підключена до виклику RPC після логіну (могла
лишитись стара логіка, яка перевіряє неправильну умову стану користувача).

## Що НЕ чіпати

- Схему бази даних, вже виконані міграції.
- RPC-функції `create_game`/`join_game`/`start_game` — якщо в діагностиці
  (завдання 3) з'ясується, що саме вони повертають помилку, тоді написати
  тут окремо, що саме не так, а не переписувати їх наосліп.
